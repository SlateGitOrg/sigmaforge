Selection (`uv run python scripts/fetch_sigmahq.py --select`): for each of 13 directories the
sorted list of `.yml` paths is sampled at evenly spaced indices up to a quota
(process_creation 70, builtin 25, registry 15, linux 20, aws 10, ...; quotas are in the script
and the manifest). No rule was added or removed by hand. Verification:
`make fetch-sigmahq` re-downloads every listed file and fails on any checksum mismatch.

DRL 1.1 permits redistribution and modification provided the rule's author attribution and
reference fields are kept; the files are stored byte-for-byte as published.

## Example rules — `examples/rules/`

Nine rules written for this project (`author: sigmaforge examples`), covering every supported
construct the README advertises. MIT, like the code.

## Example events — `examples/events/`

`windows.jsonl` holds 21 **synthetic, benign** events generated by
`scripts/make_example_events.py`. They imitate Sysmon / Windows Security / Linux process field
names; users, hosts and addresses are invented (RFC 1918 and documentation ranges
198.51.100.0/24, 203.0.113.0/24). No real telemetry, no malware: "malicious-looking" command
lines are inert strings. `expected.json` holds the hand-labelled verdict for every rule, which
`tests/test_golden.py` checks against the evaluator.

## Generated test data

The Hypothesis strategies in `tests/strategies.py` generate rules and events at test time;
nothing is stored except Hypothesis' local example database (`.hypothesis/`, git-ignored).
